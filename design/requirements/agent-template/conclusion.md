## 入口与目标

将模型、系统提示词、Skill 和配置参数保存为可复用的 Agent 模板，当前租户成员共同维护。

原型为独立 HTML/CSS/JavaScript，只使用内存示例数据，刷新重置；不依赖正式 frontend，不请求业务接口、真实模型，不存凭证。入口 `prototype/index.html`，尺寸评审 `prototype/preview.html`。

从仓库根目录启动：

```sh
python3 -m http.server 5190 --bind 127.0.0.1 --directory design/requirements/agent-template/prototype
```

列表：`http://127.0.0.1:5190/`；编辑：`http://127.0.0.1:5190/?view=editor`；工具可附加 `&tab=tools`，上下文为 `context`，运行为 `runtime`。尺寸评审：`http://127.0.0.1:5190/preview.html`。端口被占用时先核对已有预览服务；确需另起服务时同步修改端口和 URL。

## 已确认的参数与管理规则

页面顶部横向页签：**基本信息、工具、上下文、运行设置**，切换展示对应内容，统一保存。

| 栏目 | 参数 | 默认及语义 |
| --- | --- | --- |
| 基本信息 | 模板名称 | 必填，当前租户内唯一 |
| 基本信息 | 描述 | 选填，说明用途 |
| 基本信息 | 运行模型 | 下拉选择当前租户模型，必填 |
| 基本信息 | 温度 | 选填，默认留空；留空时不发送温度参数 |
| 基本信息 | 系统提示词 | 选填，纯文本，不解析变量 |
| 基本信息 | 启用模板 | 默认启用；停用仍保留配置、允许编辑，不能用于新任务 |
| 工具 | Skill | 左侧可选、右侧已选；固定内容版本，手动切换更新 |
| 上下文 | 上下文预算 | Token 正整数，可空；默认空表示使用当前模型最大上下文；自定义值不能超过已知模型上限 |
| 上下文 | 历史摘要 | 初版固定方式，没有模式选择器 |
| 上下文 | 摘要模型 | 默认跟随运行模型，允许独立选择 |
| 上下文 | 保留最近消息数 | 默认 10 条，按实际消息条数而非对话轮数计算 |
| 运行设置 | 最大循环次数 | 非负整数，默认 0；0 不限次数，只统计主模型调用，工具和摘要调用不计入 |
| 运行设置 | 运行超时 | 分钟，允许非负小数，默认 0 不限时；0.5 等于 30 秒 |

上下文预算计算完整输入加输出预留。输入包含系统提示词、历史摘要、保留消息、Skill/工具说明和工具结果。系统提示词独立保留，不计入最近消息 N；工具调用与结果成组保留，实际保留条数可略大于 N。输出预留数量和触发时机由系统处理，不增加最大输出 Token 或阈值输入框。

模型最大上下文等能力在**模型接入**维护：能可靠获取则预填，不能则手填。信息缺失时允许保存模板，但标记配置不可用，使用前补齐；不能把空预算解释为无限上下文。模型接入维护权限沿用现有规则，不随模板全员可编辑而扩大。

模型、连接、Skill 已停用：原有模板可以继续维护和保存，显示配置不可用，不能运行。新选择只提供当前租户的可用资源。模板自身启停与依赖可用性是独立状态，不互相覆盖。

模板租户共享，所有当前租户成员可以创建、维护和删除。**保存直接更新配置，初版不做发布、模板历史版本或审批**；并发控制的 revision 仅为内部修订号，不作为产品版本展示。Skill 固定版本不受此决定影响。

## 本轮收敛的交互方案

以下为可评审的实施建议，除上节明确确认的规则外，不伪称用户已经逐项认可。

1. **列表进入整页编辑**：新增、编辑共用四页签；名称/描述搜索，全部/启用/停用筛选。卡片展示名称、描述、模型、Skill 数量、更新时间、自身状态；依赖异常另示“配置不可用”。
2. **统一保存**：栏目切换不提交、不丢输入。页头和页签随滚动保持可见；修改后显示“未保存”。保存成功仍在当前栏目，失败保留所有草稿；保存中禁用输入、离开与重复提交。已保存且未改动时不重复发送保存。
3. **整页校验**：一次找出所有栏目错误，页签标记待调整数量，字段下方展示原因，切换并聚焦第一个错误。修正时更新错误，不叠加浏览器气泡。依赖停用提示不当作阻止保存的表单错误。
4. **切换模型**：未指定摘要模型时立即跟随运行模型；独立指定的摘要模型不变。空预算随模型上限变化；自定义预算保留，超过新上限即提示并提供“调整上下文预算”跳转，不静默截断或改回默认。
5. **Skill 双栏**：左侧搜索、复选；选择即进入右侧，取消或移除即离开草稿。同一 Skill 不重复，默认选添加当时最新版本；已选版本较旧时提示“有新版本”，仍保留原版，用户通过版本下拉手动切换。零个 Skill 也允许保存。已停用的旧绑定可保留/移除，不能切换到其其他版本。
6. **离开保护**：取消、回列表、导航、切换租户前如有未保存内容，提示继续编辑或放弃，默认焦点在继续编辑。关闭/刷新用浏览器未保存提醒。Ctrl/Cmd+S 保存，页签支持方向键/Home/End，弹窗 Esc 取消。
7. **复制与删除**：复制最近保存的配置，进入未保存的新模板；自动生成不重名的“副本”名称。若原页面有修改，说明复制基于已保存配置，可取消返回先保存。删除二次确认，仅删除模板和绑定，不删除模型、Skill 或包内容。初版暂无任务等引用；未来有引用时须先补齐对应删除规则。
8. **默认值与说明**：基础表单不主动填温度和预算；展示当前继承的模型上限。循环和超时各有 0 的含义；摘要条数解释不是对话轮数。启停提示停用后仍可编辑。不要在产品界面展示 revision、接口或存储细节。

默认实施约束：名称 trim 后 1–80 字、描述最多 300 字、提示词最多 20,000 字；最近消息数正整数且至少 1，不额外设任意业务上限；循环非负整数；时限使用非负有限十进制分钟，不能截断成整数。数字技术边界由 API/数据库一致校验，不另起用户问答。

温度必须结合模型能力验证，不能把原型示例的 0–2 视为所有模型的共同范围。建议模型接入同时维护温度是否支持及可用范围；不支持时显示说明并要求清空显式温度，未知时显式温度使配置不可用但允许保存，留空仍可用。切换模型不静默删除已有显式值。该兼容细节在正式开发时与模型接入一并落实，原型尚未模拟所有供应商差异。

## 数据、权限与保存契约（开发建议）

候选模板字段：`id, tenantId, name, description, enabled, modelId, systemPrompt, temperature, contextBudgetTokens, summaryModelId, keepRecentMessages, maxIterations, timeoutMinutes, revision, createdBy, createdAt, updatedAt`。

- `temperature=null`：不发送；`contextBudgetTokens=null`：继承所选模型上限；`summaryModelId=null`：跟随运行模型。保存的是继承关系，不复制当时上限。
- `description`、`systemPrompt` 使用字符串，空字符串代表无内容；`enabled` 为布尔。次数和时间的 0 有明确含义，不能当空值。POST/PUT 要求发送完整配置，缺少必填键返回字段错误；三个可空字段仍显式传 null，避免遗漏与清空混淆。
- Skill 绑定：`templateId, tenantId, skillId, versionNumber, position`；请求数组顺序为添加顺序，初版无拖动排序。`skillBindings:[]` 清空 Skill；省略不等价于清空，作为不完整请求拒绝。唯一约束 `(templateId,skillId)`。
- 名称在租户内 trim 后唯一，大小写是否敏感按当前项目数据约定落实，并让前后端一致；唯一索引兜底并发。同一名称可以存在于不同租户。
- 保存基本信息和 Skill 绑定同一事务完成。后端校验当前成员、全部资源租户归属及版本存在性，不能只依赖前端下拉。
- 原有不可用绑定允许原样保留/移除；新增或变更引用时仅允许可用资源。页面打开后资源被停用：旧绑定仍可保存；新绑定则返回字段错误并保留草稿，要求重新选择或移除。服务端必须比较旧绑定，而不是将所有停用引用统一拒绝。
- 模型、Skill 和版本受模板引用时限制物理删除，停用可以保留关联。需要同删除事务同步检查，Skill 对象清理前完成保护。原型不实现其他模块的删除入口，这项正式行为必须有服务端测试。
- 模型接入补充能力字段，旧记录可空；不能用任意数值回填为可信上限。能力元数据缺失会影响依赖可用性，但不会改写模板启停状态。
- `available` 和 `unavailableReasons` 由依赖与能力信息派生，不作为用户可写字段；未来可用于新任务的条件至少包含模板启用且配置可用。保存成功不代表 Agent 运行能力已经实现。
- 保持 Session/CSRF。未登录 401，非成员 403；跨租户资源与不存在资源统一 404，不泄露名称。平台管理员不能仅凭平台身份跳过租户成员限制。既有成员管理/模型接入权限不改。
- 不在模板存 API Key、连接地址和协议凭证；按同租户模型引用由已有模型接入解析。

## 候选接口与错误

沿用现有 `ApiResponse` 包装与分页结构，以下列出 data。路径为建议的新增 `agent-templates` 能力，不代表已有 API。

| 方法/路径 | 请求 | 结果与副作用 |
| --- | --- | --- |
| GET `/api/tenants/{tenantId}/agent-templates` | `page=1,size=12,q?,enabled?`；enabled 不传为全部 | `{records,total,page,size,counts:{all,enabled,disabled}}`；按 updatedAt/id 倒序，q 匹配名称和描述；counts 在 q 下计算但不受 enabled 筛选影响 |
| GET `/api/tenants/{tenantId}/agent-templates/{id}` | 路径 ID | 全部配置、revision、模型/Skill 展示信息、available/unavailableReasons |
| GET `/api/tenants/{tenantId}/agent-templates/{id}/copy-name` | 路径 ID | 未占用的建议副本名称字符串；保存仍以唯一约束校验 |
| POST `/api/tenants/{tenantId}/agent-templates` | `requestId`、全部配置、`skillBindings:[{skillId,versionNumber}]` | 原子创建，返回详情；复制复用创建接口 |
| PUT `/api/tenants/{tenantId}/agent-templates/{id}` | `requestId,baseRevision`、全部配置和 Skill 绑定 | 原子替换，revision 加一；启停随整体保存，不另发即时开关请求 |
| DELETE `/api/tenants/{tenantId}/agent-templates/{id}` | `baseRevision` 查询参数 | 删除模板和绑定，data 为 null；不删模型/Skill |

请求标识绑定当前租户、操作者、目标、方法和规范化载荷。网络失败后同内容重试复用标识，已经完成则返回原结果；同标识不同内容为 409，修改内容生成新标识。不得先触发修订冲突再处理已完成的同请求重试。服务端按项目现有模式实现，不另建通用框架。

400 字段错误附字段路径/原因（重复名称、错误数字、预算超上限、非法版本或新绑定被停用）；409 修订冲突保留全部草稿，提示其他成员已更新，不自动覆盖，提供保留草稿/取消及重新加载。重新加载须明确会放弃草稿。401 回登录，403/404 显示不可访问并可回列表；网络/5xx 保留表单并允许重试。后端错误结构沿用 shared 约定扩展必要字段，不把资源停用伪装成保存失败。

正式列表采用现有分页与约 300ms 搜索防抖；切换搜索/状态回第一页，删除末条回退有效页。列表计数随相同搜索范围更新。原型少量示例同步过滤，无分页请求、真实鉴权、并发编辑或幂等服务。

## 实施顺序与验收

正式开发获得授权后：先对照最新 checkout 核对模型接入、Skill、权限和导航；补模型能力元数据；按能力分包新增模板数据与接口；再接四页签页面和导航。数据库手动 SQL 按 `backend/sql/README.md`，一表一文件；模型能力增量迁移先执行，模板主表后执行，绑定表最后执行，写明依赖已有 identity/llm/skill 表，不自动执行生产 SQL。

新增前端 `frontend/src/features/agent-templates/`，工作区入口接 `IdentityWorkspace.tsx`；后端使用独立模板能力包，普通 CRUD 优先 MyBatis-Plus。补齐已有 `LlmAccessService`、`SkillService` 的引用保护；不要修改 Agent 循环提案来假装运行时已完成。

验收重点：

1. 新建只填唯一名称与可用运行模型即可保存；温度/预算空、摘要跟随、最近 10 条、次数和分钟均 0、启用且零 Skill。
2. 四页签切换保留数据；多处错误一次标出，自动聚焦首个；修改后错误消除，保存成功保留当前页签，失败不丢字段。
3. 预算为空随模型上限变化；显式值超新模型上限提示并拒绝保存；未知上限可以保存但配置不可用。摘要跟随或独立选择的行为分别正确。
4. 循环 0、超时 0/0.5 能保存并读回；循环小数/负数、时限负数和预算 0 拒绝；不得把超时小数截断或把预算空当 0。
5. Skill 多选右侧同步、零项允许；固定版本保存后保持，新版本只提示；旧停用绑定可维护，新停用绑定不能加入；模型同理。
6. 模板停用仍可编辑；依赖异常另外标识；修复依赖不会自动启用停用模板。删除和复制按前述规则执行。
7. 多成员并发更新返回冲突，跨租户 ID 不可读写；同租户名称唯一、不同租户允许同名；重复提交不创建重复对象，模型/Skill 受引用不能删除。
8. 宽/窄/移动端与键盘检查通过；返回、取消和切租户有草稿保护；无匹配、空、加载、失败重试均可恢复。

原型检查：`node --check design/requirements/agent-template/prototype/app.js`；仓库检查：`./scripts/check.sh repo`。原型已用示例数据检查；正式浏览器验证覆盖页签、版本切换、保存、离开保护及 1440/768/390 宽度。浏览器使用临时假后端，真实后端由一次性 PostgreSQL 集成测试独立验证。正式实现按改动范围执行 `./scripts/check.sh frontend`、`backend`；涉及数据库/Mapper 额外 `integration`，全部使用假模型。
