## 1. 用户目标、当前范围与代码入口

租户需要配置自己的模型供应商连接，同一租户可为同一供应商保存多个账号或环境。每条连接下面维护多个模型，后续 Agent 模板选择某个模型，并在模板层配置温度、Token 上限等运行参数。供应商名称与接口协议是两个不同概念：例如供应商叫“阿里云百炼”，该连接使用哪种兼容协议由用户手选。

本需求的正式产品范围是来源和模型的后端 CRUD、工作区管理页面、查询供应商候选模型并选择导入，以及租户权限和凭证保护。当前交付是讨论文档和纯交互原型，正式实现尚未开始。Agent 模板、模型推理执行、温度/Token 设置、模型计费、自动模型同步和更多协议不在本需求实现范围。

实施前必须重新读取根目录、`backend/`、`frontend/` 的 AGENTS。实际可复用入口：

- `backend/src/main/java/io/github/chalmery/loopcraft/identity/service/IdentityService.java`：`current` 与 `tenant(actor, tenantId, manage)`。后者允许平台管理员跨租户读取或管理，普通账号需要成员关系，管理需要 OWNER。成员管理方法 `requireOwner` 是另一条既有规则，不得因本模块而扩大其权限。
- `backend/src/main/java/io/github/chalmery/loopcraft/shared/ApiResponse.java`：统一响应 `{code,message,data,traceId}`，成功 `code=0`，失败沿用 HTTP 状态码。
- `frontend/src/features/portal/IdentityWorkspace.tsx`：认证后工作区外壳与 section 导航。新增“模型接入”对所有能访问当前租户的用户可见，不受仅 OWNER 可见的“工作区与成员”导航限制。
- `frontend/src/features/admin/TenantManagement.tsx` 与 `AdminListParts.tsx`：表格、编辑侧栏、删除确认、字段附近错误及成功 toast。
- `frontend/src/lib/api.ts`：同源请求、Session/CSRF 与响应校验。正式页面复用该入口。

## 3. 实施建议与剩余评审项

以下为依据已确认需求补全的技术契约建议，不应误写为用户逐项指定的方案。开发 Agent 可按这些默认值实施；若实际代码要求调整，应维护本文而不是静默改变产品行为。

- 来源名称在同租户内唯一；模型 ID 在同来源内唯一。输入 trim 后比较，供应商模型 ID 保持大小写且不做别名转换。
- 供应商名称自由输入，不将厂商品牌枚举当成协议驱动。可提供常用名称建议，但增加新品牌不需要增加协议代码。
- 可保存尚未配置凭证的来源，`hasApiKey=false`；查询候选模型要求配置凭证，未配置时 409 并提示先完善连接。无鉴权本地服务若后续需要，应由独立需求放宽，不静默假设。
- 停用来源时不逐条覆盖其模型的 enabled。用于后续模板选择的有效状态为 `source.enabled && model.enabled`，重新启用来源后各模型保留原状态。
- API 根地址由用户完整提供版本前缀，例如 `https://api.example.test/v1`；适配器追加 `/models`，不能擅自重复拼接 `/v1`。不接受完整 `/models`、`/messages` 或 `/chat/completions` 作为根地址。

当前唯一阻塞“设计已定稿”的事项是页面尚未由用户评审认可。未来 Agent 模板执行需要额外确定：来源/模型停用后，已绑定模板的实际运行策略，以及来源协议或模型 ID 已被引用后是否允许修改；本轮只保存引用与状态，不实现或宣称模板仍可正常调用。原型中的模板引用数仅为删除保护演示，当前代码没有模板表。

## 4. 数据设计与约束

建议新建能力包 `llm`，按 `controller/dto/service/mapper/model/config` 等实际职责组织，不预建无用层。

| 表              | 字段与归属                                                                                                         | 必须约束                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `lc_llm_source` | `id`、`tenant_id`、`name`、`supplier_name`、`protocol`、`base_url`、`api_key_ciphertext`、`enabled`、创建/更新时间 | tenant 非空，租户外键限制删除；`(tenant_id,name)` 唯一；`(tenant_id,id)` 唯一供组合外键使用 |
| `lc_llm_model`  | `id`、`tenant_id`、`source_id`、`name`、`model_id`、`origin`、`enabled`、创建/更新时间                             | `(tenant_id,source_id)` 组合外键指向来源，禁止跨租户挂模型；`(source_id,model_id)` 唯一     |

`protocol` 取 `OPENAI_COMPATIBLE` 或 `ANTHROPIC_COMPATIBLE`；`origin` 取 `MANUAL` 或 `DISCOVERY`，仅用于展示添加方式。ID 分配沿用当前项目惯例。来源名称、供应商名称、模型显示名 1–80 字符，模型 ID 1–160，URL 最多 2048。enabled 默认 true。来源下允许没有模型。

凭证仅由服务端加密保存。建议使用带随机 nonce 的 AES-GCM，租户 ID 作为认证附加数据，密文带版本。主密钥通过环境配置提供；保存非空凭证而主密钥缺失时拒绝操作，不退化成明文。所有查询只返回 `hasApiKey`，不回显密钥、掩码尾号或密文。清除同时删除密文，不返回原值。字段长度按所选加密封装实际确定。

SQL 位于 `backend/sql/llm/create_llm_source.sql`、`create_llm_model.sql`，每表一个无数字前缀的文件，表和字段使用简短中文 COMMENT。手动执行顺序为 identity → source → model，写进 SQL README，不引入 Flyway。

## 5. 权限、状态与事务

所有接口先确认当前登录用户和租户访问权限，再用 tenantId 和 sourceId/modelId 共同限定资源查询。没有租户访问权限返回 403；有租户权限却查到其他租户的资源 ID 作为本租户资源访问时返回 404。成员写操作 403。平台管理员的特权限于本需求规定的来源/模型管理，不扩大其他业务权限。

来源/模型启停是 PATCH，停用后仍可查询和管理已有配置。模型查询、手动添加和编辑是管理动作，普通成员不能通过直接调用接口绕过按钮限制。

删除模型：检查同租户实际模板引用；有引用 409，并说明可改为停用；无引用删除。删除来源：在一个事务中检查其全部模型引用；有任一引用则全部拒绝，无引用则删除子模型后删除来源，任一步失败全部回滚。未来模板关联使用限制删除的外键与一致锁定顺序，保证并发新增引用不会绕过检查；当前模板模块不存在时不得伪造引用数据或额外实现模板业务。

租户删除需要因新增 source 外键保留现有关联业务数据删除保护。前端成功隐藏按钮不构成权限校验。

## 6. 建议接口契约

全部位于 `/api/tenants/{tenantId}`，使用现有 Session/CSRF 与 ApiResponse；写接口均要求管理权限。列表默认 page=1、size=20，size 上限 100，返回 `records,total,page,size`，关键字 q 可过滤名称/模型 ID。默认按 updatedAt 倒序、id 倒序，禁止客户端自由 SQL 排序。

| Method / 相对路径                                       | 请求                                                    | 响应及副作用                                                                                                                    |
| ------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| GET `/llm-sources`                                      | `page,size,q?`                                          | 分页来源；包含 `id,name,supplierName,protocol,baseUrl,hasApiKey,enabled,modelCount,updatedAt`                                   |
| POST `/llm-sources`                                     | `{name,supplierName,protocol,baseUrl,apiKey?,enabled?}` | 201，来源视图；只建立来源                                                                                                       |
| GET `/llm-sources/{sourceId}`                           | 无                                                      | 来源详情，字段同来源视图                                                                                                        |
| PATCH `/llm-sources/{sourceId}`                         | 上述可编辑字段任选，加 `clearApiKey?`                   | 200 更新视图；仅更新提供字段                                                                                                    |
| DELETE `/llm-sources/{sourceId}`                        | 无                                                      | 200 `data:null`；按 B-08 事务删除来源与模型                                                                                     |
| GET `/llm-sources/{sourceId}/models`                    | `page,size,q?`                                          | 分页模型：`id,sourceId,name,modelId,origin,enabled,updatedAt`；未来实际引用数可按模板模块能力扩充                               |
| POST `/llm-sources/{sourceId}/models`                   | `{name,modelId}`                                        | 201 模型视图，origin=MANUAL，enabled=true                                                                                       |
| PATCH `/llm-sources/{sourceId}/models/{modelRecordId}`  | `{name?,modelId?,enabled?}`                             | 200 模型视图；路径是本地记录 ID，请求 modelId 是供应商模型 ID                                                                   |
| DELETE `/llm-sources/{sourceId}/models/{modelRecordId}` | 无                                                      | 200 `data:null`，有实际模板引用时 409                                                                                           |
| POST `/llm-sources/{sourceId}/model-discovery`          | `{cursor?,limit?}`，不接收前端密钥                      | 查询已保存的连接，不写模型表；返回 `{records:[{name,modelId}],nextCursor,supported:true}`                                       |
| POST `/llm-sources/{sourceId}/models/import`            | `{models:[{name,modelId}]}`，最多 100 项                | 在来源下按模型 ID 幂等添加，返回 `{created:[ModelView],skippedModelIds:[string]}`；已有模型不覆盖、不重新启用；同请求重复项去重 |

PATCH 通用规则：字段省略表示保留；必填文本 null/空串/全空格为 400；未知协议为 400。`apiKey` 省略或空白表示不更换；非空表示替换；`clearApiKey=true` 明确清除；同时提交非空 apiKey 与 clearApiKey=true 为 400。启停独立修改 enabled，不要求重新提交密钥。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [
      {
        "id": 101,
        "sourceId": 11,
        "name": "模型显示名",
        "modelId": "supplier-model-id",
        "origin": "MANUAL",
        "enabled": true,
        "updatedAt": "2026-10-18T08:00:00Z"
      }
    ],
    "total": 1,
    "page": 1,
    "size": 20
  },
  "traceId": "request-trace"
}
```

错误使用已有 envelope，data=null：400 输入错误，401 未登录，403 无管理/租户权限或 CSRF 拒绝，404 本租户无此资源，409 重复名称/ID、存在引用或凭证未配置，502 供应商失败，504 查询超时。供应商未实现模型列表时返回 200 `{records:[],nextCursor:null,supported:false}` 供手动添加回退；不要把凭证失败当作“不支持”。上游错误需归一化，不把原始响应、凭证或连接认证信息直接写回用户/日志。

## 7. 模型查询与导入流程

UI-01：管理者选来源 → 点击查询 → 服务端检查权限/资源归属并解密凭证 → 按该来源的协议驱动调用其模型列表 → 归一化模型 ID 和名称 → 前端展示候选。OpenAI 与 Anthropic 原厂均提供模型列表接口，但兼容服务是否支持由实际响应判断，不按厂商品牌硬编码完整模型目录。实施时核对所用协议官方文档的鉴权、版本头和分页约定：

- https://platform.openai.com/docs/api-reference/models/list
- https://platform.claude.com/docs/en/api/models/list

候选列表不自动持久化、不自动禁用或删除旧模型。已存在 ID 显示“已添加”，其他结果可搜索、多选和批量添加。导入成功更新模型列表和计数；重复候选跳过而非覆盖。查询失败时保留已保存模型和表单上下文，允许重试或手动添加。只有明确“不支持”才走不支持提示。

调用均在服务端完成，推荐连接/请求有界超时（如请求 15 秒）、响应体与候选数上限、只跟随可控分页；禁止将任意上游错误当成成功。配置保存只做字段校验，不把真实查询成功作为能否保存的必要条件。来源未启用也允许管理员维护模型，后续模板选择检查有效状态。

## 8. 页面、原型及状态

UI-02：入口在当前租户工作区的“模型接入”。左侧来源显示名称、供应商、协议、模型数及状态；选择后右侧展示连接概况和该连接的模型列表。窄屏先来源、后详情，表格允许局部横向滚动，表单可铺满窄屏。

UI-03：来源新增/编辑侧栏包含供应商名称、连接名称、协议、API 根地址及 API Key。已保存密钥只显示已配置，输入留空保留；清除使用独立显式选择。保存校验失败在表单附近显示并保留输入，成功关闭并反馈。正式版复用现有 shadcn Select/Sheet/Form，静态原型的原生控件仅用于交互表达。

UI-04：模型表格含显示名称、模型 ID、添加方式、启用状态和操作。手动添加/编辑只输入名称和模型 ID；不包含温度、Token、提示词。停用保留记录和引用；删除先确认，无引用才执行；存在引用提示改为停用。

UI-05：普通成员可选择来源、搜索与查看模型，所有新增/编辑/查询供应商/导入/启停/删除按钮隐藏；负责人/全局负责人可见。正式版仍以服务端权限为准。角色演示器只属于原型，不进入正式产品。

正式页面的状态：初始化局部加载；列表空时提供管理者新增入口；查询中禁用重复查询并保留旧数据；失败局部重试，不清空已有列表；表单提交中禁止重复操作；普通成员与未配置凭证有清晰只读/配置状态。用户主动成功操作 toast，字段错误内联；避免重复反馈。原型用可切换“成功/不支持/失败”的查询结果表达这些行为，未模拟真实网络等待。

原型与正式版差异：原型全部在内存中、不分页、不请求或存储密钥、不验证真实供应商能力；引用数是假数据，且无模板运行行为。原型包含未来模板导航占位，正式版不能因此新增模板实现。原型不进入 frontend 构建，开发时按 feature 重新组合已有组件。

本轮原型核查：JavaScript 语法检查及无浏览器、无网络的逻辑模拟检查已覆盖导入去重、密钥保留/清除与冲突、输入校验、成员只读、引用删除保护、启停状态和级联删除。迁移后的真实浏览器视觉与键盘检查尚未完成：浏览器访问自动审批拒绝授予本地站点读取权限。此限制不代表页面已通过视觉评审；当前保持 review。

## 9. 实施顺序与变更边界

1. 先读取并对照当前 identity 权限、响应、SQL、前端工作区，核实与本基线的差异。
2. 建立 source/model 表及服务、Mapper、DTO、Controller；复用 tenant 检查与 Session/CSRF；补充加密凭证配置和 SQL 执行说明。

4. 将确认的 UI 按正式组件实现到 `frontend/src/features/llm-access/`，通过现有 api request 模块调用真实接口，在 IdentityWorkspace 增加所有可访问租户成员可见的入口。
5. 验证数据库约束、权限、CRUD、候选/导入与页面状态；补充受影响 README。此阶段需有正式实施授权。

允许新增的产品能力仅限本需求。不要把原型 HTML 直接放进正式路由，也不要把当前模型示例或协议行为猜测当作供应商事实。未来模板引用限制应在模板模块真正建立时通过服务/外键接入，不创建虚假的模板表来满足本原型。

## 10. 验收场景

| 编号 | Given / When                                           | Then                                                                      |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------- |
| A-01 | 同一租户为同一供应商新增不同连接名                     | 均可保存，各自模型互不混淆；跨租户同名允许                                |
| A-02 | 在同租户保存重复连接名，或在同来源保存重复模型 ID      | 409；不新增或覆盖已有数据；表单保留输入                                   |
