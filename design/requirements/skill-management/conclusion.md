## 已确认范围

- 租户独立的 Skill 管理，一个 Skill 有基本信息，并关联多个完整包内容版本。
- 完整包包括 `SKILL.md` 和配套文件；支持压缩包上传、在线新增和在线编辑。文本文件可编辑，图片等二进制文件通过上传替换。
- 每次编辑内容后保存，追加一个版本。旧版本只允许查看，第一版不做回退、从旧版本发起编辑或版本说明。
- 本轮只聚焦管理，不接入 Agent，不执行脚本，不增加 Git 管理。
- 对象存储后端选定 RustFS；存储能力独立成模块。RustFS 是实际存储服务，Java 文件管理组件是否采用 X-File-Storage 尚未选定。
- 卡片首页展示基本信息；详情分“基本信息”和“内容”，基本信息下方有版本列表，每行详情进入对应内容版本。
- 卡片、表单保持紧凑，卡片取消装饰小图标；侧栏保留 Skill 图标，独立归入“插件”分组（目前唯一菜单）。标签以小框逐项展示和编辑，一个 Skill 对应多个标签。

## 基本信息与包内文件独立（用户已确认）

平台基本信息以用户确认的表单为准。新建导入允许复用包内字段作为初值；创建后两者互不自动覆盖：

- 新建导入时，先选择 ZIP，再进入编辑页。用 `SKILL.md` frontmatter 的 name 预填标识和显示名称、description 预填描述，允许用户修改后确认保存；缺失或解析失败时手动补充。首次保存后保持基本信息与包内文件独立。
- 修改平台名称、描述时，不改写 `SKILL.md` 或任何已保存的内容版本。
- 上传或在线编辑文件时，即使其中含名称、描述，也仅作为文件原文保存，不拿这些字段查找 Skill、判断 Skill 名称冲突或变更权限。
- 上传到已有 Skill 时，归属由当前选中的 Skill 及可信租户上下文确定。例如向 Skill A 上传包，包内 name 写 B，仍是 A 的内容，不改 A 的名称，也不创建或修改 B。
- 新建平台基本信息的唯一性校验与包内容无关；稳定标识是否租户内唯一、创建后是否可修改仍是独立字段规则，尚待确认。
- 第一版不要求版本保存平台元数据快照，也不自动生成、删除或同步包内 YAML 字段。保存内容版本只冻结文件集合与文件内容。

## 权限（用户已确认）

| 资源 | 当前租户普通成员 | 当前租户负责人 OWNER | 平台管理员 |
| --- | --- | --- | --- |
| 租户自建 Skill | 可新增、编辑、删除 | 可新增、编辑、删除 | 对租户自建资源的额外跨租户管理范围尚未明确 |
| 系统内置 Skill | 可查看，不可管理 | 可管理，包括编辑、删除 | 可管理，包括编辑、删除 |

用户通过专门澄清确认：内置 Skill 所说的“租户”是租户负责人 OWNER。内置 Skill 不采用“只能复制为自建后修改”的限制。

普通成员不因能管理自建 Skill 就能修改其他租户资源。正式接口必须同时验证身份、租户、Skill 归属和来源；前端隐藏按钮不代替后端授权。成员管理等现有接口权限不在本轮改动范围。

来源标记建议命名 `origin`，值 SYSTEM / CUSTOM；新增和上传默认自建。普通表单不能将自建改为内置。如何初始化内置包、内置是否为每租户独立记录仍待明确，不能擅自变成平台共享资源库。

## 状态与标签

- Skill 支持启用/禁用；用户明确禁用的含义是不提供给模型。本轮只做管理端状态及其持久化，不实现模型侧发现、缓存或运行中任务行为。
- 状态作用于 Skill 主记录，建议默认启用，不为各内容版本增加独立启停状态。
- 禁用与删除是两个操作；禁用保留基本信息和版本，可在管理端查看。删除的确认方式、数据与对象清理规则待确定。
- 标签属于平台基本信息；输入 Enter 或点击添加生成小框，框内可移除；空白忽略，同 Skill 内相同文本去重。
- 标签逻辑一对多；第一版建议不引入公共标签字典或标签管理中心。标签修改不改动包内容。

## 页面与主要流程

1. 卡片列表：按名称、标识、描述和标签搜索；显示最新版本、文件数、来源和禁用状态，点击卡片任意位置进入只读基本信息。
2. 基本信息：维护名称、描述、标签和状态；来源仅展示。当前原型另有稳定标识字段，其规则待确认。
3. 版本列表：按新到旧显示版本号、最新标记、文件数、保存时间与详情。不提供版本说明列或输入。
4. 最新内容：有管理权限者可编辑多个文件，然后统一保存为新版本。旧版本只读，不显示编辑、恢复或回退入口。
5. 在线新增：填写平台信息，再编写内容。原型建议首次保存同时创建 Skill 和 v1；取消临时草稿不创建记录。是否允许先建空 Skill 还待确认。
6. 压缩包新建：先导入 ZIP，再进入编辑页，预填包内 name 作为标识与名称、description 作为描述；用户可修改后保存。已有 Skill 上传新包的归属是当前 Skill，新包作为内容版本的保存流程需补齐原型。
7. 文本文件原样编辑，包含 SKILL.md 的全部内容；不单独隐藏 YAML 头。二进制文件只替换，不作为文本编辑。
8. 未保存时离开详情、切换租户或角色预览，先提示继续编辑或放弃；模拟保存失败保留输入且不增加版本。

原型权限模式提供普通成员、负责人、平台管理员和额外只读预览，均为假身份。全部数据仅存页面内存，刷新重置，不接正式 API、RustFS 或凭证。压缩包只演示选择和模拟载入，尚未实现真实解压上传；删除、已有包上传与二进制替换等交互仍需补齐，不得把原型示例当作后端能力。

## 存储与开发边界

当前 backend 是单 Maven 应用。建议先新增 `storage` 能力包，连接 RustFS，提供对象上传、读取、删除与元信息查询；Skill 模块负责包处理、版本清单和业务授权。是否拆 Maven 子模块或独立服务未确认。

建议部署侧配置存储 Endpoint、Bucket 与凭证，不新增租户自配存储页面。使用私有 Bucket，按可信租户上下文生成对象归属，授权后才能访问。数据库保存对象标识，不依赖会过期的签名 URL 作为文件身份。

Skill 主记录保存平台基本信息；内容版本记录版本号、文件清单及对象关联。业务版本由应用管理，不用 RustFS 对象版本能力代替。文件全部写入并校验成功后才使版本可见；失败不产生半成品版本，已有版本保持可读。

重复提交、多人并发、对象清理失败重试、文件限额与部署数据卷/备份需要开发交接时明确。当前复用既有存储模块，不新增存储依赖。Skill 三张表已在一次性数据库验证；开发数据库当前未启动，尚未应用 SQL，未部署或连接真实 RustFS。

## 验收场景

- 平台名称 A、包内名称 B 时，上传保存后平台仍显示 A，包内仍保留 B。修改平台描述不改变任何内容版本；编辑包内描述不改变平台描述。
- 同租户普通成员可管理自建 Skill；内置 Skill 只能查看。负责人和平台管理员可管理内置 Skill。跨租户越权访问按正式契约拒绝。
- 每次保存内容只新增一个版本；保存失败时保留输入，不出现新版本。多个文件在一次保存中形成同一个版本。
- 查看旧版本时只能读文件，没有编辑、回退或版本说明功能；最新内容仍按权限允许编辑保存新版本。
- 禁用后管理端仍可看到基本信息及历史；模型侧不提供的语义在未来运行时接入时另行验证，本轮不伪造执行证据。
- 标签逐项添加移除并保存，基本信息更新不修改文件内容。

## 正式实现入口

- 后端：`backend/src/main/java/io/github/chalmery/loopcraft/skill/`，controller / dto / service / mapper / model / config 分包。
- SQL：`backend/sql/skill/create_skill.sql` → `create_skill_version.sql` → `create_skill_tag.sql`，逐表手动执行。

- API：`/api/tenants/{tenantId}/skills`，完整请求与响应字段见 DTO、API 类型和根 README。
- 错误语义：400 参数/包校验；401 未登录；403 租户或内置写权限；404 所属租户内不存在资源/版本；409 标识、修订或基线冲突；503 存储未启用/不可用。文件与元数据原文不写入日志。
- 删除重试：`SkillObjectCleanup`；上传回滚补偿由事务回调尽力完成。如对象写入与补偿删除同时失败，需按 RustFS 清单核对孤立对象，此限制见 SQL README。
