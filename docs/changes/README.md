# 需求变更记录

本目录用于较复杂的单次需求，不是所有改动的必经流程。

适合建立需求提案的情况：

- 需求跨越多个前后端模块或需要分阶段实施。
- 存在重要架构/依赖选择，或需求边界和验收条件需要先讨论清楚。
- 需要保留方案取舍和验证计划，方便实施期间及后续评审对照。

一个需求使用一个简短、稳定的目录名，并从 [`_template/proposal.md`](./_template/proposal.md) 开始。先讨论并确认目标、范围、验收条件和关键选择；确认后补全实施计划，再开始实现。实现完成后记录验证结果和需要更新的稳定文档。小型、明确的修复直接使用 Issue/对话即可，不必创建目录。
